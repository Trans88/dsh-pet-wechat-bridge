# Little Pet · 独立 AI 宠物

自己的宠物、人设和记忆。通过本地网页、微信 Bot 或 QQ 官方机器人，与同一个性格的小伙伴聊天、互动。

**从 v0.3.0 起，正常运行不再需要 dsh、dsh-pet 或任何 dsh 插件。** 后端直接调用你配置的模型服务，聊天记录和长期记忆保存在本机 SQLite 数据库。仓库沿用原来的 `dsh-pet-wechat-bridge` 地址与 Git 历史，项目已经独立。

## Windows 桌宠（v0.10.0）

新增透明桌面小伙伴：高清桃铃狐、拖动、右键互动、聊天气泡、托盘、大小与置顶设置。源码用户双击 `start-desktop.cmd`，或安装开发依赖后运行 `npm run desktop`。已有网页、聊天记忆和养成状态可以继续使用。详见 [桌宠启动与下载说明](docs/desktop.md)。

桃铃狐默认采用 **627×627 / 帧** 的高清四姿态素材；原来的 **192×208 / 帧** 逐帧动画仍可在设置中选择。

## 开始使用

需要 **Node.js ≥ 22.13.0**，建议使用 Node 24。Windows、macOS、Linux 均可运行。

```powershell
git clone https://github.com/Trans88/dsh-pet-wechat-bridge.git
cd dsh-pet-wechat-bridge
npm ci --ignore-scripts --no-audit --no-fund --registry=https://registry.npmjs.org/
npm start
```

浏览器打开 **http://127.0.0.1:3210**。Windows 也可以双击 `start.cmd`，首次缺少依赖时会安装锁文件依赖。

1. 进入「设置」，填写聊天服务 **Base URL、模型名、API Key**。保存后立即生效。
2. 可以选择宠物形象、修改名字、欢迎语和人设；回到「小窝」开始聊天。
3. 进入「连接」→「连接微信」，复用已有登录；首次使用则扫码。机器人运行期间需要保持电脑与本程序开启。
4. 想让宠物自己找话题：进入「探索」→「打开小红书登录」，在独立窗口扫码后会自动识别登录，也可直接点「现在去逛逛」；检查登录会保留窗口。填写兴趣，可选开启配图/视频片段分析，再勾选允许自动探索并保存。探索页也可退出或切换小红书账号。详见 [自主探索使用说明](docs/exploration.md)。
5. QQ 在「连接 → QQ」单独配置 AppID / AppSecret；详细步骤见下方「QQ 接入」。摸头、投喂等小窝互动不需要模型 API Key。

默认预填 DeepSeek 的 `https://api.deepseek.com` 与 `deepseek-flash`，需你自己的有效 API Key。也可以连接提供 Chat Completions 兼容接口的本机模型，例如其 `http://127.0.0.1:端口/v1` 地址。模型可用性、计费和图片能力以实际服务商为准。

网页没有演示回复：未配置模型时会明确提示。测试不会使用你的真实模型或发送微信消息。

## 宠物形象

v0.4.0 内置「桃铃狐」原始动画图集，升级后默认显示粉发狐耳形象。待机眨眼、摸头挥手、等待回复时思考，点击「打个盹」显示休息姿势。所有图片随项目提供，无需登录 ChatGPT。

在「设置 → 形象与人设 → 宠物形象」可切换高清桃铃狐、原版桃铃狐和经典蓝猫，保存后立即生效。形象与名字、人设独立；升级保留你的现有名字、人设和数据。想让名字也叫「桃铃狐」，在同一页修改名字即可。

动画尊重系统的减少动态效果设置，后台标签页或其他页面暂停播放。素材来源与帧映射见 [web/assets/README.md](web/assets/README.md)。

## 查询 DeepSeek 余额

使用 DeepSeek 官方 API 时，无需新增配置，余额查询复用聊天模型已保存的 API Key（`PET_API_KEY` 环境变量仍优先）。支持 `https://api.deepseek.com` 和 `https://api.deepseek.com/v1`，包含末尾斜杠的写法。

- 打开「设置 → 聊天模型」，自动查询账户的可用余额、充值余额、赠送余额及查询时间；点击「刷新余额」重新读取。修改地址或 Key 后请先保存。
- 在本机「小窝」发送 **查询余额**、**还剩多少钱**、`/余额` 或 `/balance`，宠物直接查询并回复，不调用聊天生成接口。QQ / 微信未绑定主人身份，不能查询账户余额。
- 人民币可用余额低于 **5 元** 时，查询结果中显示提醒；账户不可用时显示余额不足。此提醒只在查询时产生，不会定时后台查询或发送消息。
- 这是 API 账号的共享余额，不是单个模型或宠物的独立预算；人民币和美元分别展示，不相加，不估算剩余 token。历史回复仅代表当次查询结果。
- 未配置 Key、不支持的服务、网络超时、认证失败分别提示；查询失败会清除页面旧金额，不会显示为 0。更换账号时丢弃尚未完成的旧查询。

依据 [DeepSeek 官方查询余额接口](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)。密钥仅由本机后端发送到固定官方地址，不返回网页、不交给聊天模型；余额请求最长等待 10 秒。真实余额需在你的电脑上使用已配置的 Key 验证。

## QQ 接入

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，获取 **AppID / AppSecret**，启用需要的单聊和群聊能力。接入的是机器人账号，不是接管你的个人 QQ。具体可申请能力以账号后台为准。
2. 根据开放平台后台配置测试成员、测试群、IP 白名单，事件接入选择 **WebSocket**。需要沙箱时，在宠物的 QQ 配置里勾选沙箱环境。这一路径不需要把宠物网页暴露到公网。
3. 在宠物「连接 → QQ」填入凭据，保存后点击「连接 QQ」。状态变为「已连接」才表示网关握手完成。也可以通过环境变量 `QQBOT_APPID`、`QQBOT_SECRET` 提供凭据；环境变量优先，改动后重启。
4. 默认私聊仅允许指定联系人，群聊关闭。先向机器人发一句话；回到连接页，找到收到的联系人 OpenID，点击「填入名单」再保存。OpenID 不是 QQ 号或群号。群聊同样可以先 @ 机器人，再把收到的群 OpenID 加入名单并启用「仅指定群」。也可自行选择开放范围。
5. 在 QQ 发文字即可聊天；发 `/宠物` 查看状态和互动菜单。群里需要 @ 机器人。更换凭据或沙箱环境会断开旧连接，请重新连接。仅修改名单即时生效。勾选「启动宠物时自动连接 QQ」可在下次启动时自动连接。

QQ 支持文字和单张图片（JPG、PNG、GIF、WebP），可附带文字提问；群里仍需要 @ 机器人。图片沿用设置里的聊天模型图片能力或独立图片模型，并保留在当前发言者的会话中供后续追问。单图下载上限 8 MiB、等待最多 20 秒；沿用现有图片处理，超过 700 KiB 的 GIF/WebP 需先转成普通 JPG。每次请只发送一张图片，暂不读取 QQ 语音、视频或其他文件。超长回复会截短到约 4000 字符。主动推送、QQ 扫码绑定和 QQ 按钮菜单未纳入本次实现。

**表情包无法识别 / 回复说收到乱码：** 旧版只把 QQ 文字传给模型，没有传图片附件，还可能把 `<faceType=...>` 等表情标签当作文字。现在收到图片附件就传真实图片；只收到名称或编号时，会解析可用的名称并明确说明没有原图，不把标签或 Base64 当作图像证据。这类表情请长按保存到相册，再通过 QQ「图片」按钮发送。GIF 可作为图片输入，不代表能理解完整动画过程；图片模糊或文字太小仍可能识别不准。DeepSeek 官方 `deepseek-flash` 支持图片，使用时需在设置中勾选图片能力；其他模型以服务商实际支持为准。

每个 QQ 机器人、私聊联系人、群中的不同发言者分别保存历史、记忆和养成状态。群回复仍会显示在群内，但不会把其他群成员的私聊历史放进上下文。未在名单内的消息不会调用模型，也不会保存消息正文；连接页仅显示近期联系人/群的 OpenID 供配置。

网关由腾讯 SDK 负责 token 更新、心跳与重连；失败时连接页显示说明。网络中断时，已经提交给 QQ 的回复可能仍会完成；无法确认是否发送成功的消息不自动重发，避免重复刷屏，需要时请重新发一条消息。

**连接按钮一直灰着 / 鼠标转圈：** v0.7.1 及更早版本在连接成功后也会禁用按钮并显示等待光标，不能只靠按钮颜色判断是否在线。v0.7.2 起会直接显示「正在连接 / 已连接 QQ / 重试连接」，并把说明和错误放在按钮旁边。初次连接和断线重连各最多等待 60 秒，可点击「取消连接」。如果提示本地服务超过 12 秒未响应，检查启动终端并点击「刷新状态」。更新后请重启程序、按 Ctrl+F5 刷新页面。

- **已连接但不回复：** 默认私聊名单为空，先发一句话，再把下方出现的 OpenID 填入名单并保存。群聊需启用对应范围并 @ 机器人。名单不会阻止网关建立连接。
- **凭据 / HTTP 401、403：** 核对 AppID 和配套的 AppSecret、机器人权限及公网出口 IP 白名单；错误码本身不能唯一确定是哪一项。
- **DNS / 网络 / 证书错误：** 按页面给出的错误码检查运行宠物电脑的网络、DNS、代理、系统时间或证书。浏览器能打开 QQ 后台不等于 Node.js 能访问 QQ 接口，不要关闭证书验证。
- **网关 4914：** 核对机器人上线状态、测试范围与沙箱开关。需要反馈时复制按钮下方的错误或终端 `[QQ]` 提示即可，不要发送 AppSecret。

协议依据：[腾讯 QQ Node.js SDK 使用说明](https://github.com/tencent-connect/qqbot-nodejs/blob/main/USAGE.md)。代码锁定 `@tencent-connect/qqbot-nodejs@1.0.5`，不依赖 dsh 插件。自动测试使用模拟网关；真实账号权限、IP 白名单、消息额度需要本机配置后联调。

## 自然聊天与 QQ 表情包

v0.9.0 默认开启「设置 → 形象与人设 → 聊天风格 → 自然俏皮」。保留现有名字、性格和记忆，闲聊通常一两句，减少固定的“主人～”、动作描写、客服口吻和每轮结尾追问；允许轻松接梗和有自己的看法。用户认真问问题时仍完整回答。可切换「按自定义人设聊天」，按自己的提示词控制语气。网页、微信、QQ 及探索主动分享共用这套语气，实际效果取决于所用模型。

QQ 在同一次聊天生成中判断是否适合配图，从内置桃铃狐「好耶 / 抱抱 / 啊这 / 笑不活了」四张静态表情中选一张或不发，无须额外画图 API。在「连接 → QQ → 自动配表情包」选择：

| 频率 | 最小间隔 | 说明 |
| --- | --- | --- |
| 偶尔一张（默认） | 2 分钟，且相隔至少 3 轮 | 闲聊自然配图，严肃求助不配图 |
| 活泼一些 | 45 秒，且相隔至少 2 轮 | 仍由模型判断，不是每轮发送 |
| 关闭 | 不发送 | 仅保留文字回复 |

两个间隔条件都要满足；同一群共享限额，避免多人同时 @ 刷图。每次最多一张，不连续重复同一张，间隔在重启后保留。模型没有合适的判断时只回文字。聊天窗口中的图片记录只在 QQ 确认发送成功后显示。当前自动配图用于 QQ 被动回复，以普通图片消息发送；网页和微信不自动发这些表情，图片本身是内置资源，发送不要求视觉模型。

文字先发送，图片失败不会重复发送文字，连接页会显示「表情包未确认送达」。图片上传、发送各最多等待 20 秒；断开连接、修改名单或关闭配图后，不会继续从已完成的上传发起图片发送。已经提交给 QQ 的请求无法撤回，结果不明确时不自动重发。聊天指令如 `/抱抱` 仍使用原来的本地互动反馈，不消耗模型。

## 和宠物一起玩

小窝增加六个互动按钮；点击宠物本身也能摸头。投喂会增加饱食度，玩耍/跳舞会消耗精力，睡觉按经过的时间恢复精力。吃饱、睡着或玩累时会给出对应反馈。每次互动有短暂间隔，状态和最近 20 条小记保存在 SQLite，刷新或重启不会丢失；亲密度不会因离开而下降。

聊天中也可以发送 `/摸头`、`/投喂`、`/抱抱`、`/玩耍`、`/跳舞`、`/睡觉`、`/起床`，这些命令使用本地逻辑，不消耗模型调用。`/宠物` 查看状态；普通文字仍交给聊天模型。网页和不同通道会话的养成状态各自保存。互动动画兼容桃铃狐与蓝猫，并遵循系统减少动态效果设置。

## 从旧版升级

先停止旧桥接进程。在原工程目录更新源码、安装依赖、启动：

```powershell
git pull --ff-only
npm ci --ignore-scripts --no-audit --no-fund --registry=https://registry.npmjs.org/
npm start
```

- 保留本机整个 `data/`，已有的 `account.json` 与 `state.json` 继续用于微信登录、游标和队列。
- 新配置保存为 **`pet.config.json`**，首次启动自动创建；不覆盖旧的 `config.json`，也不读取 dsh 的模型密钥。
- 新数据库为 `data/pet.sqlite`。**旧 dsh-pet 的人设和聊天记忆不会自动迁移**，请在新设置中填写人设，并把希望保留的重要事实加入记忆。
- 独立应用启动后，在网页连接微信。首次安装后需要填一次模型配置。
- 使用不同目录部署时，先停止原程序，再复制 `pet.config.json` 和整个 `data/`；不要同时运行新旧通道。
- 如需临时回到旧宠物，断开独立应用的微信通道，启动旧 dsh/pet，再运行 `npm run legacy:wechat`。它使用旧 `config.json`。

## 图片与语音配置

### 图片

在设置中选择确实支持图片的聊天模型，并勾选图片输入。勾选不能把文字模型变成视觉模型。

如果主模型不支持图片，可以开启「独立图片模型」，单独配置服务地址、模型和密钥。含图片的对话上下文交由这个模型回答，不会把聊天模型的密钥自动发给另一家服务商。

每条消息支持一张图片，最大 8 MiB。大于 700 KiB 的 PNG/JPEG 会缩放压缩，较大的 GIF/WebP 需要先转 JPG。每个会话保留最近 12 张图片，本次模型上下文最多携带 3 张历史图片和当前图片。较旧图片被清理后，需要重新发送原图。

### 语音

**网页语音对话：** 配好聊天模型后，打开「小窝」→「开始语音对话」，按浏览器提示允许麦克风。说完后识别内容会自动发给聊天模型，宠物朗读回复，读完后继续听下一句。录音时也可点「说完了」立即结束本句；宠物说话时可点「打断，换我说」。点击「结束语音对话」、离开小窝、切到后台或关闭页面会停止收音与播放。停止不会撤回已经完成并保存的聊天。

这是轮流说话的语音对话；宠物朗读时不收音，避免把自己的声音再次发给模型。没有唤醒词、后台常驻监听或同时听说。话筒图标保留为**语音输入**：识别结果追加到输入框，编辑确认后再发送。开始语音对话前需先发送或清空现有草稿和图片。

在「设置 → 语音对话」选择输入、输出方式：

| 设置 | 自动模式的行为 | 可选方式 |
| --- | --- | --- |
| 语音识别 | 已启用 STT 时使用该服务，否则尝试浏览器识别 | 浏览器识别 / 已配置的 STT 服务 |
| 宠物声音 | 已启用 TTS 时使用该服务，否则使用浏览器提供的系统声音 | 系统声音 / 已配置的 TTS 服务 |
| 文字聊天也自动朗读 | 默认关闭，升级后不会自行开口 | 开启后朗读本页新发送的文字聊天回复；历史记录不自动播放 |

可选择浏览器识别/系统朗读语言和系统音色，调整语速、系统声音音调，并试听当前声音。语言设置只作用于浏览器能力，独立 STT/TTS 的语言支持由所用模型和音色决定。语速同时影响系统朗读与 TTS 音频播放速度；音调只影响系统声音。TTS 音色在「图片与声音 → 语音合成 TTS」填写，修改服务设置后先保存再试听。

浏览器识别无需另填 STT 密钥，但不是所有浏览器都支持；部分实现会把声音发送给浏览器厂商的联网识别服务，是否可用取决于浏览器、地区和网络，不能保证离线识别。系统声音无需另填 TTS 密钥，可用音色和是否联网取决于系统与浏览器。相关行为见 [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition) 和 [音色的本地/远程服务属性](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)。浏览器方式不可用时，可显式选择独立服务；程序不会在识别失败后偷偷切换服务商。

独立 STT/TTS 在「设置 → 图片与声音」配置：

| 设置 | 要求 |
| --- | --- |
| STT | 支持 `POST {baseUrl}/audio/transcriptions`，multipart 文件上传，JSON 返回 `text`；需要服务商的模型名和密钥 |
| TTS | 支持 `POST {baseUrl}/audio/speech`，接收 `model`、`voice`、`input`、`response_format: mp3`，返回 `audio/mpeg` |

这些接口是兼容协议适配，并不表示任意服务商都可直接使用。启用前需要核对服务商的协议、模型和音色。DeepSeek 的聊天配置不会自动提供 STT/TTS。

网页每句最长 60 秒，录音最大 8 MiB。STT 录音模式会在检测到说话后按设置的停顿时间结束，默认 1.5 秒；自动检测需要正常运行的 Web Audio，无法使用时可手动点「说完了」，最长时间仍生效。浏览器识别模式由浏览器判断句子结束，不使用这个停顿设置。未听到说话或识别/播放失败时结束本次语音流程，显示原因，不无限重试。

网页会把长回复拆成每段最多 500 字符依次朗读，避免只读前半段。底层 TTS 单次接口仍最多合成前 500 字符，微信语音回复仍沿用其长度限制。微信语音没有自带转写时会解码为 16 kHz WAV，按 20 秒分段调用 STT。

微信语音回复模式：`voice` 仅对语音输入附加 MP3、`always` 每次附加 MP3、`off` 只发文字。未启用 TTS 时可设为 `off`。文字发送成功后，即使音频生成失败也不会重复发送文字。

## 记忆与数据

- 网页、每个微信绑定账号分别拥有独立历史和长期记忆，不默认认定为同一个人。更换机器人或微信账号会使用新的会话空间。
- 聊天记录最多保留每会话 500 条，模型读取最近最多 24 条；长期记忆最多 100 条，每条 1000 字符。第一版不做自动事实提取或无限上下文。
- 「记忆」中删除一条事实不会删除原聊天中的对应文字。如希望后续聊天不再引用，请同时清空相应会话的聊天记录。
- 清空聊天会删除会话正文、图片与缓存回复；保留去重 ID，防止已处理的微信消息重复生成。
- 网页可查看微信记录和管理其记忆；微信记录页为只读，不会从网页代发微信消息。
- 关闭程序后备份整个 `data/` 和 `pet.config.json`；SQLite 运行中可能有 `-wal` / `-shm` 文件，不要仅复制正在写入的主数据库文件。

`pet.config.json` 包含模型密钥，`data/account.json` 包含微信登录凭证；数据库包含聊天和图片。这些本机数据不提交 Git，不要上传或分享。

可以用环境变量提供密钥，优先于配置文件：`PET_API_KEY`、`PET_VISION_API_KEY`、`PET_STT_API_KEY`、`PET_TTS_API_KEY`。程序不会自动读取 `.env` 文件。网页不会返回已保存的密钥；密码框留空保持原值。更换服务域名且没有填写新密钥时，会清除原服务的文件密钥，环境变量仍需你自行调整。

当前服务只监听 `127.0.0.1`，所有请求校验 Host，私有接口必须携带本次启动的随机授权码。首页单独校验来源；接口不依赖可能缺失或被改写的浏览器来源头，不开放 CORS。修改端口可编辑 `pet.config.json` 的 `port` 并重启；不提供公网/局域网部署开关。

## 命令

```powershell
npm start                  # 启动独立网页与宠物核心
npm run check              # 检查本机配置，不调用模型
npm run wechat             # 在独立应用已运行时，单独启动微信通道
```

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 没有 API Key 不能聊天 | 进入设置填写；原 dsh 中的模型配置不会自动导入 |
| 模型 401/403 | 检查密钥、余额/权限和服务商地址 |
| 模型 404 | 检查 Base URL 是否需要 `/v1`，以及模型名；不要把 `/chat/completions` 填进 Base URL |
| 模型 429 | 服务限流或配额不足，检查服务商后台 |
| 图片无法理解 | 使用视觉模型，并正确配置图片能力或独立图片模型 |
| 浏览器识别不可用或网络失败 | 查看「语音对话」中的输入方式；浏览器识别依赖浏览器能力与网络，可改用已配置的独立 STT |
| 麦克风无权限或没有设备 | 从本机 `http://127.0.0.1:3210` 打开，允许站点麦克风权限并检查系统输入设备 |
| STT/TTS 失败 | 检查选中的独立服务是否启用、接口是否兼容、模型和音色是否正确；聊天密钥不会自动用于语音服务 |
| 自动朗读被浏览器阻止 | 点击回复旁的「朗读」重试；仍失败时检查站点播放权限或改用其他音色 |
| 说完后仍在录音 | 点击「说完了」；STT 停顿检测需要 Web Audio 正常运行，背景噪声也可能影响检测 |
| 微信凭证失效 -14 | 断开微信通道，重新扫码，成功后再连接 |
| 独立宠物尚未启动 | 先启动 `npm start`，再运行微信命令 |
| 3210 端口被占用 | 关闭另一份应用，或修改新配置的 `port` |
| 页面无样式、设置无反应，控制台 app.js/style.css 返回 403 或 MIME 错误 | 更新到 v0.3.1 或以上，停止旧进程后重新 npm start，再按 Ctrl+F5 刷新 |
| 已通过 127.0.0.1 打开，页面有样式但聊天或设置提示「请从本机地址打开宠物页面」 | v0.3.1 的接口来源校验可能误拦截；更新到 v0.3.2 或以上，停止旧进程、重新 npm start 并按 Ctrl+F5。127.0.0.1 本来就是当前电脑，无需修改模型密钥或微信绑定 |
| 页面授权过期 | 后端重启会更换令牌，刷新网页即可 |
| `node:sqlite` 不存在 | 升级到 Node.js 22.13 或以上；某些 Node 22 版本会打印 SQLite 实验性提示 |
| npm 下载 502 | 使用上述 npm 官方 registry 命令，不修改全局代理配置 |
| 回复发送超时 | 可能已送达，不盲目重发；需要时重新提问 |

## 开发与验证

架构见 [docs/architecture.md](docs/architecture.md)，开发流程见 [CONTRIBUTING.md](CONTRIBUTING.md)，版本记录见 [CHANGELOG.md](CHANGELOG.md)。

自动测试覆盖微信桥接、媒体、模型与记忆隔离、配置密钥保护、本机 HTTP 鉴权，以及探索调度、时区/免打扰、取消、来源验证、重复抑制、升级迁移和主动消息。联合 HTTP/DOM 测试覆盖探索、连续语音、QQ 和养成互动共存，以及保存各类设置时保留其他功能配置。QQ 回归还覆盖导入/握手挂起、总超时、取消和重试、迟到回调、重连期限、错误脱敏、按钮等待状态与本地请求超时恢复，以及图片附件进入模型、会话隔离、表情标签、下载限制和下载期间撤销权限。

语音测试使用模拟识别、录音与合成接口，覆盖完整回合、停止后晚到回调、设备清理、错误恢复与配置持久化。QQ 使用模拟网关。测试不使用真实模型密钥、麦克风或平台账号，也不发送真实微信或 QQ 消息。

本轮 Chromium 启动受执行环境的 socket 权限限制，未完成真实浏览器视觉与窄屏验收。小红书扫码、登录保持与网页选择器，QQ 平台权限、IP 白名单与消息额度，Windows 麦克风、中文识别、实际音色及服务商 STT/TTS，以及微信端到端仍需用户电脑联调。代码不会绕过验证码或登录限制；平台页面变化会报告读取失败，不会生成虚构浏览结果。主动分享仅在小窝接收，微信和 QQ 主动推送尚未启用。
