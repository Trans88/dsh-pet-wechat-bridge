# 工程结构与处理流程

| 文件 | 职责 |
| --- | --- |
| `bridge.mjs` | 命令入口、扫码登录、实例锁、长轮询及退出处理 |
| `config.mjs` | 首次生成本机配置，保留已有配置 |
| `lib.mjs` | 微信与 pet 客户端、地址校验、持久化队列和去重 |
| `media.mjs` | 图片解密/压缩、SILK 解码、语音识别及 MP3 回复上传 |
| `dependency-check.mjs` | 无网络二维码、JPEG、SILK 运行检查 |
| `test/` | HTTP 模拟、队列恢复、媒体协议与配置回归测试 |
| `data/` | 仅本机的凭证、轮询游标、队列与锁；不纳入 Git |

## 消息流

微信 iLink 轮询返回消息后，程序先校验扫码账号私聊与消息 ID，再把游标和收件箱一起持久化。队列串行处理，调用本机 dsh-pet 的聊天接口，并把回复发回原 Bot 会话。模型选择、人设、记忆由原 pet 管理，桥接不保存另一份模型 API Key。

文字直接进入聊天接口。图片先下载、解密和限制大小，再作为 pet 图片附件传递。语音优先使用消息自带转写，否则解码 SILK 并分段调用 pet 语音识别接口。需要语音回复时先发送文字，再调用 pet 语音合成、加密上传 MP3，作为微信文件发送。

## 中断恢复

队列状态为 `queued` → `generating` → `ready`，发送前进入 `sending`。附加媒体先进入 `preparing`。进程重启时，已生成但未发送的回复可继续；正在生成或正在发送的结果不确定，因此跳过并提示用户，避免自动重复调用模型或重复发送。媒体准备阶段可恢复，已发文字不会因此再发送一次。这是保守的恢复策略，不保证每条消息一定送达。

## 外部边界

- dsh 服务只允许本机地址；桥接自身不监听公网端口。
- 微信 API/CDN 目的地址受到校验，下载受大小限制，重定向不自动跟随。
- 认证状态、游标、去重记录按绑定账号关联；重新登录会重置桥接消息状态。
- pet v0.4.7 接口是当前适配基线。插件或微信协议变化需要重新核对。

## 后续开发方向

待验证：Windows 上图片识别、无微信转写时的语音识别、MP3 回复及断网恢复。

可选扩展：转发 pet 配图/表情、媒体格式扩展、发布打包脚本。微信原生语音条需要单独验证协议和编码要求，当前版本不支持。群聊和自主浏览尚未纳入实现。
