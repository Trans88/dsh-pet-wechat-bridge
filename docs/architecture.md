# 独立宠物架构

v0.8.0 的默认运行路径没有 dsh 依赖。

## 消息流

网页直接调用本地 `/api/chat`。微信消息经 `bridge.mjs` 与 `LocalPet` 转为同一接口的请求，由 `PetCore` 加入本会话的人设、长期记忆和近期历史，再请求模型。成功后用 SQLite 事务写入用户消息、回复与去重记录。生成失败不写入半个对话。

微信桥接的已有收件箱保持原格式。消息 ID 同时传给核心，避免核心成功、桥接未收到响应时重复消耗模型。无法确认已发送的微信消息仍沿用保守策略，不自动重发。

## 网页语音

`PetVoice` 独立于 DOM，通过 `getConfig`、`api`、`onState`、`onTranscript`、`onError` 与页面连接。`app.js` 负责状态呈现、草稿和原有 `/api/chat` 调用，语音对话仍使用 `web:owner` 的历史、记忆及消息幂等。不会从网页向微信会话代发语音或文字。

状态依次为请求麦克风、听取本句、转写、等待回复、播放回复；播放结束再进入下一轮。浏览器识别使用 `SpeechRecognition` 或 `webkitSpeechRecognition`，服务端识别使用 `getUserMedia` + `MediaRecorder`，完成后提交 `/api/stt`。浏览器识别服务可能联网，其音频传输由浏览器实现负责，不经过本地 `/api/stt`。

默认输入方式在已启用 STT 时选用该服务，否则选浏览器识别；输出方式同理优先 TTS，再使用 `speechSynthesis`。显式选择的服务不可用时报告错误，不在失败后静默切换提供方。`voice.language` 仅控制浏览器识别和系统合成语言，不新增服务端 STT/TTS 的请求参数。系统音色列表可能异步就绪，通过 `voiceschanged` 更新。浏览器音色可能来自本地或远程服务，不保证离线。

麦克风与扬声器分时工作，不做唤醒词或全双工。每句录音最多 60 秒、8 MiB；实际 MIME 通过 `MediaRecorder.isTypeSupported` 选择，等待最终 `dataavailable` 和 `stop` 后再上传。服务端模式用 Web Audio 分析信号，检测到有效声音后按 `voice.silenceMs` 判断停顿；AudioContext 无法运行时依然可手动结束录音，60 秒上限保留。浏览器识别的句末判定由浏览器控制。

每次开始产生新的 generation 和 AbortController；停止会使旧回调失效、取消请求、释放录音轨道和 Web Audio、停止播放并清理定时器与 Blob URL。麦克风授权晚于停止返回时立即释放轨道。页面隐藏、离开小窝、切换会话和退出触发清理。服务端通过响应连接关闭中止模型/媒体请求；停止不回滚此前已经成功保存的聊天。

话筒输入只追加到草稿，语音对话则自动发送识别结果。`voice.autoSpeak` 默认为 false，只控制普通文字聊天的新回复；手动朗读和已经开始的语音对话可以播放。网页按最多 500 字符分段朗读完整回复；服务端 TTS 接口和微信既有单次限制保持不变。`voice.rate` 控制系统合成语速和 MP3 播放速度，`voice.pitch` 仅用于系统合成。

语音配置校验后与已有配置一同持久化，读取旧文件时自动补默认值但不强制重写文件。新增配置不保存服务密钥；STT/TTS 密钥沿用原有隔离、脱敏规则。模拟测试覆盖控制流与取消竞态，真实识别准确率、音色及设备权限仍需要实机验证。

## 会话与记忆

- 网页使用 `web:owner`。
- 微信使用 `wechat:sha256([botId,userId])`，避免账号切换混用记忆。
- QQ 使用 `qq:direct:sha256([appId,kind,groupOpenid,senderId])` 与 `qq:group:sha256(...)`，隔离机器人、群和群内发言者；群内回复仍是群内可见。
- 各会话共享宠物人设，各自保存聊天与长期记忆；没有隐式跨渠道身份合并。
- 同会话同时只能生成一次，第二个请求返回 409。已有微信队列仍串行处理。
- 长期记忆通过页面或 `/remember` 添加；不自动把模型猜测变成事实。
- 每会话保留 500 条消息和 12 张最近图片，模型读取最近 24 条消息及最多 3 张历史图片。

## 配置与密钥

新配置位于 `pet.config.json`，旧 `config.json` 只在 `--legacy` 模式读取。配置先校验再原子写入；保存失败不会替换内存配置。API 返回 `hasKey`，不返回密钥内容。环境变量优先于文件。

聊天、视觉、STT、TTS 的密钥分别配置，不跨服务继承。变更服务 origin 时，不会把原文件密钥静默发给新服务；环境变量由操作者自行维护。

## DeepSeek 账户余额

带本机令牌的 `GET /api/model/balance` 调用 `Models.balance()`，仅使用 `Config.provider('model')` 返回的有效密钥；不复用视觉、STT 或 TTS 密钥。`pet/balance.mjs` 只接受官方 HTTPS origin 及根路径或 `/v1` 前缀，始终请求固定的 `https://api.deepseek.com/user/balance`，不跟随重定向。请求设置 10 秒超时并传播 HTTP 断开信号；响应校验币种、布尔状态及十进制金额字符串，保留小数精度，只返回明确字段与查询时间。错误不会回显上游响应或密钥。

余额不缓存，每次查询读取最新结果；返回前核对地址和有效密钥，配置变更则丢弃旧查询。页面进入设置或保存设置后查询，并提供手动刷新；原有 5 秒状态轮询不查询余额。编辑地址/Key 会取消请求并清空旧显示；前端另设 15 秒等待上限，防止按钮持续禁用。低余额提醒只展示在本次结果中，人民币阈值为 5 元，不新增调度任务。

`PetCore` 在聊天模型调用前识别明确的余额命令，只有 `web:owner` 可以查询；其他会话返回本机查询入口，不访问账单或调用生成接口。成功结果以带查询时间的普通聊天回复保存，沿用请求 ID 去重；用新消息再次查询才读取新余额。跨渠道未建立主人身份绑定，不能因为联系人获准聊天就授予账户余额访问权限。系统提示注明历史余额不代表实时余额。

## HTTP 边界

服务只监听 IPv4 loopback。所有请求的 Host 必须匹配当前端口的 `localhost` / `127.0.0.1`。公开 JS、CSS 使用精确文件白名单；含令牌的首页与不含用户数据的 `/api/health` 继续校验 Origin/Fetch Metadata，拒绝外站来源和仅同站请求；Origin 为 null 时须同时明确标记 same-origin。

其他接口一律要求 `Authorization: Bearer <本次启动的 32 字节随机令牌>`，使用常量时间比较。已经持有正确令牌的请求不再被 Origin/Fetch Metadata 二次否决，兼容来源头缺失、null 或被改写的环境。接口不使用 Cookie、URL 查询参数或来源头作为授权凭据；不返回 CORS 允许头，浏览器跨域预检无法通过，普通跨站请求也无法携带正确令牌。网页 fetch 限制为 same-origin 并省略 Cookie。微信子进程从本机 `data/pet-runtime.json` 读取令牌；重启后旧令牌失效。不要在后续改动中开放 CORS 或引入隐式 Cookie 鉴权而不重新评估这一边界。

这一区分遵循显式随机令牌与自定义请求头的鉴权方式，来源校验用于保护未持有令牌的首页加载。参考 [OWASP 的令牌与 AJAX/API 请求头说明](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html#transmitting-csrf-tokens-in-synchronized-patterns)。

静态路由只有 `/`、`/app.js`、`/voice.js`、`/style.css`、`/assets/taolinghu.png`，不能请求任意磁盘文件；静态文件按 Buffer 返回，避免 PNG 经 UTF-8 解码损坏；`/favicon.ico` 返回空的 204。首页内嵌本次启动令牌，仍按私有路由校验来源。响应禁止缓存，CSP 禁止第三方脚本、iframe 和页面脚本的外部连接；用户和模型文字以 textContent 渲染。请求体限制 12 MiB，模型响应、媒体下载均有超时和大小限制。CSP 不代表浏览器自身的语音服务离线运行。

兼容模型可使用公网 HTTPS 或本机 HTTP；不跟随重定向发送凭证。原微信/CDN 的目的域名校验不变。

## 宠物外观

`pet.appearance` 仅接受 `taolinghu` 和 `blue-cat`，缺省为桃铃狐；读取旧配置不写回文件，不改变已有名字和人设。原图是随项目提供的 8 × 11 动画图集；网页以 192 × 208 单格视窗、百分比偏移与逐帧时长播放，不请求 ChatGPT。帧表和原始文件散列见 `web/assets/README.md`。

状态优先级为思考、休息、摸头、待机。切换状态会取消上一帧定时器，后台标签页、非小窝页面与减少动态效果停止定时播放；页面退出清理定时器。图片加载失败只临时回退 SVG 蓝猫，不改保存的选择。

## 生命周期

应用在成功监听后才写运行令牌。端口冲突不会覆盖已有服务的令牌。退出时取消活动请求、终止微信子进程、关闭 HTTP/数据库并删除运行文件。微信不会在程序启动时自行连接，需网页按钮或显式 CLI 命令。

## 自主探索

新增配置 `exploration`，缺省 `enabled=false`，旧配置加载时不重写磁盘。开启后后台每 30 秒检查是否到期。每轮轮换一个用户填写的兴趣，最多访问 3 篇此前未读的笔记（其中最多 1 个视频）；不自动把私聊内容扩展成搜索关键词。即使页面关闭，已开启的后台调度仍继续；停止 Node 进程则停止浏览和模型调用。

浏览器使用 `data/xiaohongshu-profile/` 独立配置目录。扫码窗口有界面，自动浏览可隐藏窗口；二者串行使用同一个目录；已有可见窗口优先复用，登录检查不关闭或导航该窗口，只有无窗口时才按 headless 设置启动。保存设置保留空闲窗口，显式停止关闭浏览器并等待进行中的操作结束。只允许 HTTPS 小红书主站导航及小红书/其 CDN 子资源，不允许任意外站、内网、弹窗或下载；禁用 Service Worker；自动浏览取消 JS 对话框，手动窗口的 alert/confirm 交由主人在探索页响应。只通过固定 DOM 提取可见标题、正文、作者和笔记媒体元素，不读取内部状态或逆向接口，不点击点赞、评论或私信。配图走限定站点且禁止重定向的有界下载；视频仅由当前浏览器解码到 canvas，播放器音轨经 MediaRecorder 采集，不打开麦克风。不读取整页截图，不绕过跨域媒体保护。会话 Cookie 仅在浏览器适配器中检查，不返回 API、模型或日志。

SQLite 增加 `exploration_notes`、`exploration_events`、`runtime_state`；messages 增加 `origin` 与 `sources`。保留 500 篇已读摘要和 100 条动态。笔记 ID 去重，不因内容 URL 参数改变而重复；读取失败不标为已读。模型失败保留待处理摘录，拒绝分享的笔记标为已评估。

每轮读取后把文字片段、媒体观察摘要、标题、作者、时间及网页会话上下文发给配置的聊天模型；不发送浏览器凭证、内容链接令牌、微信会话。模型返回受校验的 JSON 决定，只能引用确实读过的 ID；来源链接由代码从实际阅读结果附加。无法解析、引用不存在的来源或无正文时不发送。网页/记忆中的指令按不可信数据处理，模型没有通用浏览器或命令工具。

分享生成阶段不占用网页聊天锁；记录 owner 活动版本，提交前再次检查版本、配置版本、停止信号、免打扰和预算。用户开始聊天即使聊天生成失败也会延后本轮分享。assistant 消息、来源共享标记、已评估标记、预算和动态在一个 SQLite 事务中提交；没有合成 user 消息。继续追问时仅注入该会话近期消息确实引用过的摘录。清空聊天会使这些来源脱离该会话上下文。

最多每日 24 轮浏览、每轮一次分享模型请求，媒体选项开启时另外最多 3 次视觉分析和 1 次 STT；每天分享 1–10 次可配置。两次分享间隔不小于探索间隔，聊天后至少等 10 分钟；连续两次未获回复则至少等 12 小时。安静时间按指定 IANA 时区计算；相同起止表示不启用。等待条件每 15 分钟重检，避免每日一次的任务永远落在安静时段。日期、计数、轮换和下次检查时间持久化，重启不补发历史任务。每轮总超时 4 分钟。

私有 API `/api/exploration` 及其 `login`、`verify`、`run`、`stop`、`read`、`clear` 子路径沿用现有 Bearer/Host 边界，不开放浏览器配置目录。`run` 返回 202，工作独立于发起请求的网页生命周期；停止开关会持久化并取消任务。登录/验证码失败暂停自动浏览；每 30 秒仅在现有可见窗口中检查会话和「我」登录标识，不导航、不启动窗口、不处理验证码。识别成功解除暂停，仍遵守开关、免打扰和限额；手动探索重新检查实际页面，不被旧的等待登录标志永久拦住。搜索支持 explore、search_result 与 discovery/item 笔记路径，按 ID 合并链接时优先保留内容访问参数；等待任意可见卡片，分别处理无结果、纯视频和未知页面。未读由客户端实际渲染的最大消息 ID 确认，避免清除尚未显示的消息。

本版主动分享只进入 `web:owner`，不将网页身份隐式绑定到微信。微信协议资料建议回复时携带入站 `context_token`，未保证长期闲置时的主动投递，所以没有增加未经验证的微信主动发信路径。

## QQ 与养成互动

QQ 由应用内独立对象管理，只有点击连接或配置 `qq.autoConnect=true` 时才连接腾讯。异步 `start()` 不阻塞网页；generation 与 AbortController 隔离旧连接和新连接，停止时等待队列结束再关闭数据库。SDK 只订阅 group/c2c intent（1 << 25），只接受群 @ 事件，不要求 Markdown 权限。AppSecret 不返回网页或写入通道状态。

SDK 导入、token 获取、网关握手共享 60 秒总时限；每次断线后的重连也有独立的 60 秒时限，连续失败事件不会延期。只有 ready/resumed 才清除时限并标为已连接。超时终止当前代次，允许手动重试；停止不等待可能卡在 token 响应体读取的 SDK 生命周期 promise，但仍等待本地消息队列结束，防止关闭数据库后写入。迟到的 SDK 实例会被停止，回调不能改变新代次状态或处理消息。

本地状态和 QQ 控制请求有 12 秒前端超时，覆盖响应体读取；超时显示「状态暂不可用」，可取消或刷新。连接按钮旁持续展示状态、等待秒数、名单提示与错误，已连接的禁用按钮不再显示等待光标。诊断只输出固定中文说明、允许的网络错误码和数字 HTTP/QQ/网关码，绝不拼接 SDK 原始错误、响应体或凭据。

QQ 入站先做身份/类型/名单检查，再写 `qq_deliveries` 去重标记，串行调用 PetCore，发送前再次检查连接代次与当前名单。保留最近 10000 个去重 ID；发送结果不明确时不自动重投（可能漏回一条），避免重复消息。队列最多 20 条；发送目标从事件身份派生，不能由消息内容改写。历史/长期记忆继续复用 Store。断开不能撤回已经提交给平台的发送。

图片只从事件的 attachments 提取：识别 image MIME，以及文件名为图片的通用 file/octet-stream；一次一张，按实际文件头检查格式。下载只允许 qpic.cn 及其子域、multimedia.nt.qq.com、multimedia.nt.qq.com.cn、qqbot.ugcimg.cn，统一 HTTPS、无凭据/异常端口/重定向，限制 8 MiB 与 20 秒。下载后再次检查连接和名单，再把字节作为 attachment 传入 PetCore；模型与历史不接收签名下载 URL。复用图片归一化、模型路由与每人会话隔离；重复消息不重复下载。

表情标签仅解析有界 Base64 JSON 中的 text 名称；不抓取正文或扩展数据里的 URL。只有名称/编号而没有图片的独立表情直接给出确定提示，不调用模型猜图。混合文字注明没有表情图片；多图、未开启视觉能力、未知媒体类型、下载失败都明确回复，不以空占位符伪装看图。

互动使用独立 `pet_care` 与 `pet_care_requests` 表，升级只增表。互动请求用 scope + requestId 去重，数值和回执在一个事务提交；最多保留 500 个回执与 20 条小记。普通聊天收到精简虚拟状态，只有精确互动命令或本地鉴权互动接口能改变它。网页按钮固定作用于 `web:owner`，没有客户端任意指定远程会话的参数。

## 后续

QQ 多图/语音/视频/扫码绑定、桌面悬浮壳、确认后的跨渠道身份绑定、旧 pet 记忆导入，以及有明确权限范围的工具调用和主动行为。当前不执行模型生成的命令；自主浏览限于明确开启的小红书探索。

### 媒体观察与账号生命周期

`explorer-media.mjs` 在详情页提取最多 3 张配图，或一个视频前 60 秒内的最多 3 帧与前 20 秒音频。采集结果仅在内存流转；`observations.mjs` 调用既有视觉/STT 路由，将成功分析的数量、帧时间、音频区间与观察摘要写入 `exploration_notes.observation`。SQLite v3 增量加列兼容旧记录；没有正文但有成功观察的图片笔记也可分享。最终决定和后续聊天只得到摘要与范围，没有原媒体就不宣称再次观看。

每次采集及分析前后检查取消信号；视觉调用单次上限 45 秒，STT 30 秒，整轮仍为 4 分钟。验证码/登录错误暂停浏览；媒体读取或分析错误只降级相应素材，不拼造观察。不同渠道不会读取网页手记。

账号操作使用独立互斥任务，先禁用调度、取消正在读取/生成的任务，再关闭浏览器并清除固定的独立 profile 路径。停止期间迟到的启动会被 closeRevision 拒绝；账号切换期间拒绝新探索/登录请求。取消旧账号尚未分享笔记的待发送状态，同时保留聊天、记忆和预算。手动窗口 viewport=null 随窗口调整，Windows 启用 Chromium sandbox。

## 桌面宿主（v0.10.0）

v0.10.1 的源码启动器只读取版本、路径标记和可执行文件检查安装状态，避免 `require('electron')` 隐式下载后重复执行安装器。`--mirror` / `--proxy` 直接构造安装子进程的环境，不依赖用户 Shell，也不改变宿主或后端环境。安装仍交给 Electron 自带脚本完成下载、校验和解压；预加载诊断只输出错误码、HTTP 状态和固定说明，子进程下载最长 10 分钟。

小窝的 hash 页面入口先更新页面选择，等待首次 `/api/state` 完成后再读取依赖配置的记录和设置。后台退出时先取消工作，HTTP 服务收尾最多等待连接 1 秒，再关闭残余连接，避免 Chromium 预连接或不完整请求头拖到宿主的强制终止期限。

`desktop/main.cjs` 只管理窗口、托盘、显示器、用户选择的数据目录及严格白名单 IPC。渲染进程启用 contextIsolation / sandbox，禁用 nodeIntegration；外部导航、弹窗和 webview 被禁止。只有精确匹配本地 `/desktop` 的主帧可以调用窗口 IPC，网页小窝没有 preload。

`desktop/backend.mjs` 先验证现存运行时的 loopback URL 和 per-start token，再复用服务；否则以 Electron 的 Node 运行模式启动 `app.mjs --no-open`，通过 IPC 等待 ready（20 秒上限）。退出仅停止自己创建的进程，7 秒后清理挂起进程。`PET_DATA_ROOT` 将配置/数据库/微信/XHS 登录资料与只读程序资源分开；默认命令行行为仍使用源码目录。

`/desktop` 与首页采用相同的 Host / 页面来源保护；新增静态资源仍走精确白名单。`/api/desktop/state` 需本次启动 token，只返回宠物公开信息、主人养成状态和主人最后一条回复，不返回其他通道历史或模型凭据。桌宠主动轮询时不调用模型。

`web/avatar.js` 将高清 2×2 图集与原版 8×11 图集统一为姿态和帧时长；网页与桌面共享此代码。桌面基于已解码图集的 alpha 判断鼠标交互区域，Windows 主进程通过 setIgnoreMouseEvents/forward 放行透明像素。窗口使用逻辑像素，位置按当前显示器 workArea 夹取。

桌面设置只包含位置、大小、置顶和免打扰，保存到数据根目录的 `desktop.settings.json`。开机启动默认关闭，仅打包后的 Windows 程序提供菜单。打包从源文件白名单创建临时目录，仅安装生产依赖，不复制开发目录的数据或凭据。

## 自然语气与 QQ 表情回复

`conversation.mjs` 仅向普通聊天与探索分享注入语气约束，默认 natural，可用 custom 回到自定义人设。历史不会被重写，原有身份、能力边界和媒体来源约束继续保留。视觉提取与余额/本地互动命令不应用此模板。

`stickers.mjs` 保存固定四张图片的 ID、用途与路径。QQ 通过 PetCore 的第三个内部参数提供本轮候选，模型一次返回 `{text, sticker}`。用户 HTTP 输入不能传入该内部参数。解析后仅 text 入历史和请求缓存；不合法 ID 被丢弃，纯文字模型输出继续兼容，损坏的控制 JSON 不透传。命中缓存不重复执行配图回调，也不增加模型调用。

发送仍由 QQBridge 控制，目标来自入站事件身份。先发文字，再用官方 SDK uploadMedia（srvSendMsg=false、fileType=1）上传已知 PNG 字节，再复查 generation、名单和配图设置，通过 mediaApi.sendMediaMessage 被动回复同一 msg_id；SDK 负责生成各消息的 msg_seq。上传及发送各等待最多 20 秒，停止可立即解除等待。迟到上传不会继续发送；已提交的平台请求不保证能撤销。文本成功后的图片异常单独记录，不重发文字或图片。

限额状态存于 runtime_state，以 appId、私聊/群类型、接收目标的哈希为 key；群成员共享限额但聊天上下文仍按成员隔离。默认至少 120 秒和 3 轮，活泼模式至少 45 秒和 2 轮，不连续重复同一 ID。发送前先持久化预约，失败/结果不明也占用间隔，避免故障刷屏；入站 qq_deliveries 继续负责重启去重。候选受当前/近期求助文本的保守过滤约束，细致语境交给完整上下文中的模型判断，不确定时应不配图。

SQLite v4 只在 messages 增加可空 sticker 列，保存平台确认送达的固定 ID，不存图片副本。按原 assistant 行 ID 更新，清空历史后迟到回调不能重建消息。后续模型上下文只附加表情的文字说明，不把图片再次交给视觉模型。网页从服务端固定目录清单渲染预览与历史；静态服务继续使用精确白名单，不暴露任意本地路径。
